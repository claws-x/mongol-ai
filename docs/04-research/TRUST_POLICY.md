# 科研知识库证据与维护规则

## 1. 目的

防止未经核验的人物、联系方式、论文、准确率和产品能力进入 Mongol AI 的
产品决策、训练数据或对外声明。

## 2. 来源等级

### Tier A

- Unicode、ISO、W3C 等标准组织的原始文档；
- 大学、重点实验室、研究中心的官方页面；
- ACL Anthology、ACM、IEEE、Springer 等正式论文页面；
- 政府或国家标准的官方登记。

### Tier B

- arXiv 等明确标注的预印本；
- 作者或组织的原始 GitHub / Hugging Face 仓库；
- 能够核验提交历史、版本和许可的开放数据项目。

Tier B 可以证明“有人发布了这个项目或主张”，但不能自动证明质量、准确率、
安全性、许可兼容或同行认可。

### 不可单独接受

- 搜索结果摘要、百科、聚合转载、营销新闻；
- 没有 DOI、正式页面或原始文件的论文题目；
- 猜测邮箱、占位 Scholar ID、全零 ORCID；
- 没有测试集和评估脚本的准确率；
- 用西里尔蒙古文结果代替传统蒙古文结果。

## 3. 事实状态

- `verified`：来源直接支持所记录的有限事实。
- `provisional`：来源存在，但出版状态、许可、数据可用性或文字系统仍需补证。
- `rejected`：已发现虚构、矛盾或不能追溯；保留仅用于防止重新引入。

## 4. 人物信息

只记录研究角色、公开贡献和机构关系。不收集私人电话、住址，也不复制未经
核实的邮箱。合作联系必须回到机构官方目录或研究者主动公开的主页。

## 5. 数据与模型导入门槛

知识库收录不等于允许进入训练或产品。导入前必须另行完成：

1. 许可证与商业使用条件；
2. 数据来源和版权链；
3. 个人信息、敏感内容与社区同意；
4. Unicode 编码纯度和传统/西里尔文字比例；
5. 重复、机器翻译污染和转写伪语料检测；
6. 母语者抽样审核；
7. 版本化训练/验证/测试划分；
8. 可复现实验和失败样例。

## 6. 更新周期

- Unicode/W3C：每次版本或工作组更新后复核；
- 论文：每月扫描 ACL、SIGIR、LREC、ICDAR、COLING、EMNLP、arXiv；
- 机构与人员：每季度复核；
- 数据集与模型：每次准备导入产品前强制复核；
- 全库：至少每月运行链接与引用完整性检查。

## 7. 纠错

任何人都可以提交证据纠错。纠错必须说明记录 ID、原结论、反证来源和建议
状态；争议记录保持 `provisional`，直到独立来源或领域专家完成裁决。
