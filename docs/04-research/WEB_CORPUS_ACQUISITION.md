# 传统蒙古文网页语料采集规范

**状态**：S2 有效执行规范  
**版本**：1.0.0  
**日期**：2026-08-08

## 目标

用可重放爬虫从公开网站收集真实使用中的传统蒙古文文本，为连接状态、FVS、
MVS、NNBSP、词边界、标点和变体规则提供规模化证据。

采集对象是 DOM／接口中的原始字符序列，不是页面截图。截图不能告诉引擎某个
可见形态来自哪个码位、控制符、字体规则或上下文。

## 数据管线

```text
种子站点清单
  → robots 与站点规则检查
  → 限速抓取 HTML/公开接口
  → 提取可见文本与 lang/DOM 上下文
  → 传统蒙古文码位检测
  → 原文无损切片
  → 码位、控制符、词境和频率统计
  → 去重与来源追踪
  → 规则候选和反例
  → 引擎自动测试
```

## 每条样本至少保存

```json
{
  "sourceUrl": "https://example.org/article",
  "fetchedAt": "2026-08-08T00:00:00Z",
  "contentHash": "sha256:...",
  "pageLanguage": "mn-Mong",
  "text": "原始 Unicode 片段",
  "codepoints": ["U+...."],
  "leftContext": "...",
  "rightContext": "...",
  "domPath": "article/p[3]",
  "license": "known-license | site-terms | unknown",
  "redistributable": false
}
```

原文不得 NFC/NFKC 化，不得删除 FVS、MVS、NNBSP、ZWJ、ZWNJ，不得把 PUA
猜成 Unicode。清洗结果必须另存，永远不能覆盖原始层。

## 三层存储

1. **来源层**：URL、抓取时间、HTTP 元数据、内容哈希、许可状态；
2. **语料层**：原始文本切片、码位序列和左右词境；
3. **推导层**：频率、共现、位置状态、变体候选、异常和规则测试。

页面字体名称、CSS 和浏览器塑形结果可以作为实现观测附加保存，但不改变原始
文本事实。

## 发现规则的方法

对于基础字母 `b` 和变体意图 `v`，统计：

```text
count(b, joining_state, selector, left_context, right_context, source_domain)
```

候选规则必须跨页面、跨栏目和尽可能跨域验证。单站点高频模式可能只是其 CMS、
字体或转码器的特性，因此报告必须同时给出：

- 总出现次数与独立页面数；
- 独立域名数；
- 完整码位序列；
- 词内位置和左右上下文；
- 各来源之间的一致与冲突；
- PUA、替换字符和疑似转码污染比例。

统计结果提出规则，确定性引擎执行规则，反例测试推翻或收窄规则。不能把“出现
次数最多”直接等同于语言真理。

## 采集边界

- 只访问公开、无需绕过登录或访问控制的资源；
- 尊重 robots.txt、站点条款、抓取间隔和并发限制；
- 不采集用户隐私、账户页、评论者身份等无关数据；
- 未知版权的完整文章不提交进 Git；保存来源、哈希、统计和必要短片段；
- 字体文件和闭源编码表必须另行检查许可，网页可见不代表允许再分发；
- 支持缓存、断点续抓和内容哈希去重，避免重复访问站点。

## 截图的唯一用途

截图可以验证：列是否左到右、页面是否溢出、控件是否遮挡、不同浏览器是否发生
视觉回归。截图不得用于：

- 反推 Unicode 码位；
- 人工描摹所谓正确字形；
- 建立私有编码映射；
- 批准语义角色；
- 替代可搜索、可计算的原始文本语料。

## S2 第一批产物

1. `data/corpus/sources.json`：站点、范围、语言、robots、条款和许可元数据；
2. `tools/corpus/crawl.mjs`：限速、缓存、可重放采集器；
3. `tools/corpus/extract.mjs`：DOM 文本和蒙古文码位提取器；
4. `data/corpus/schema.json`：样本契约；
5. `data/corpus/stats.json`：码位、控制符、上下文和域名覆盖统计；
6. 自动测试：无损往返、控制符保留、去重、域名限速与许可闸门。

所有具体站点在进入种子清单时记录选择理由和证据日期，避免把一个站点的编码
习惯误当成整个传统蒙古文体系。
