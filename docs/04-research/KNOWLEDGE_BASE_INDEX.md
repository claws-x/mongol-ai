## 这是什么

本知识库追踪传统蒙古文数字化所需的标准、机构、研究者、论文、数据集、
模型、字体和工具。它服务于产品决策、技术实现、科研合作和后续评测，
但不把“收录”误写为“背书”，也不声称已经穷尽全球研究。

本文件索引的是**外部科研事实**。项目自身要解决的问题、第一性原理、技术边界
和当前阶段以 [`项目宪章`](../00_PROJECT_CHARTER.md) 为最高优先级事实源。外部
标准、机构、专家、字体和输入法为引擎提供证据，不拥有单独决定项目方向的权力。

机器可读事实源：

- [`data/knowledge/knowledge-base.json`](../../data/knowledge/knowledge-base.json)
- [`data/knowledge/schema.json`](../../data/knowledge/schema.json)
- [公开浏览页面](../../knowledge/index.html)

S2 的真实语言使用证据采用网页语料管线，见
[`WEB_CORPUS_ACQUISITION.md`](WEB_CORPUS_ACQUISITION.md)。知识库负责记录来源，
爬虫负责保存原始码位和上下文，规则引擎负责从跨来源证据中提出并验证规则；
不以“正确截图”连接这三层。

## 证据等级

- **A**：标准组织原始资料、大学/研究机构官方页面、正式同行评审论文。
- **B**：明确标注的预印本、原始代码或数据仓库。
- 搜索结果摘要、二手博客、营销文章、没有来源的简历和联系方式不能单独
  进入知识库。

## 文字系统边界

每条记录必须标记以下至少一种范围：

- `traditional`：传统蒙古文；
- `cyrillic`：西里尔蒙古文；
- `mixed`：明确跨文字系统；
- `unspecified`：来源无法证明具体文字系统。

“Mongolian NLP”不能自动等同于传统蒙古文研究。

## 当前重点事实

1. Unicode 17.0 是字符模型事实源；UTN #57 v4 提供塑形技术说明，但属于
   Technical Note，不是规范性背书。
2. W3C Mongolian Layout Requirements 明确传统蒙古文自上而下书写、列从
   左向右推进，并明确 U+202F NNBSP 的后缀边界语义。
3. 内蒙古大学已形成覆盖 OCR、输入、语音、翻译、转换和大模型评测的研究
   平台；2026 年 TM-Bench 是必须跟踪的新基准。
4. ACL 2024 的 MC²、EMNLP 2025 的 Lotus/CMHG、ACL 2026 的
   MonCulture-Eval 证明传统蒙古文原生语料和专门评测仍是核心瓶颈。
5. 开源资源存在，但许可证、编码质量、可复现性和传统/西里尔文字边界必须
   在导入产品前再次审核。

## 旧资料处置

2026-04-03 形成的旧研究文档是探索性材料，包含未核验人物、过时兼容性
判断和没有实验支撑的“100%”声明。它们不再是事实源，使用规则见
[`legacy/README.md`](legacy/README.md)。

## 贡献门槛

新增事实必须同时满足：

1. 有稳定 HTTPS 来源；
2. 来源类型和访问日期明确；
3. 传统/西里尔/混合文字范围明确；
4. 机构、人、成果之间的 ID 引用有效；
5. 许可未知时明确写 `unknown` 或“待核验”，不能推断；
6. 通过 `python3 -m unittest discover`。

详细规则见 [`TRUST_POLICY.md`](TRUST_POLICY.md) 和
[`COVERAGE_REPORT_2026-08-08.md`](COVERAGE_REPORT_2026-08-08.md)。
