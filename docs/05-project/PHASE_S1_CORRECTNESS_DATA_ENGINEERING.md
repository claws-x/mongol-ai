# Phase S1 — 正确性数据工程

状态：工程闭环已实现；语言学批准数为 **0**。

## 目标

S1 不以“浏览器能显示蒙古文”为完成标准。它把输入原文、编码、字形、参考材料和人工结论绑定为可复核证据，使“正确”成为可追踪的审核结果，而不是截图印象或某一种字体的默认输出。

## 已交付

- 100 条可复现种子任务：60 条 Unicode 标准化变体序列、35 个基础字符、5 个格式控制符。
- 五路原文采集：国家标准／Unicode、Onon MN、Onon MK、Onon MW、蒙科立原码。私有编码只保存，不猜测转换。
- 三路字形对照：浏览器原生、锁定 Noto + HarfBuzz、上传字体或正确参考截图。
- 码位到 glyph 的追踪：每个 SVG path 带 glyph 序号、glyph ID 和 cluster，可点击定位并记录错误类型。
- 本地证据库：IndexedDB 保存工作记录，参考字体只在当前会话使用；证据包可导入、导出。
- 审核状态机：`captured → machine_verified → linguist_verified → approved/rejected`，升级必须通过证据门禁。
- 两份 JSON Schema：任务队列和证据包均有机器可读契约。
- 234 对上下文差分探针：ZWJ 数学化 isolate／initial／medial／final，93 个标准目标参与评分，141 个范围外位置只观察。
- 可复现机器证据报告：83 条无机械冲突、16 条标准—字体冲突、1 条需要上下文。
- 生产 SVG 不再绘制 FVS/MVS/ZWJ 控制占位 glyph；原始控制信息仍保留在调试记录。

入口：[`review/index.html`](../../review/index.html)

## 审核门禁

| 目标状态 | 最低条件 |
| --- | --- |
| `captured` | Unicode 原始输入非空 |
| `machine_verified` | 锁定字体哈希 + 上下文矩阵与控制符检查已经完成；允许记录冲突，但不得称为语言正确 |
| `linguist_verified` | 机器核验 + 具名合格角色 + 明确结论 + 正确参考截图 + 输入法及字体版本 |
| `approved` | 人工核验条件 + 结论为正确 + 审核说明；Onon/蒙科立按冲突需要作为可选证据 |
| `rejected` | 具名审核者 + 错误结论 + 拒绝原因 |

合格角色当前限定为母语审核、字体工程或出版审核。门禁只能证明材料齐全，不能替代审核者的语言能力。

## 数据边界

- 不把 Unicode 的标准化变体注册解释成具体语言环境中的正确用法。
- 不把 Noto、Onon 或蒙科立任一实现单独当作绝对真值。
- 不在缺少权威映射时自动转换 MK、MW 或蒙科立 PUA。
- 不把机器塑形成功标成语言学正确。
- 参考截图会写入浏览器本地记录和导出的 JSON；上传字体字节不持久化、不上传。

## 实际执行流程

1. 引擎自动核对官方码位、有效位置、控制符和锁定字体响应。
2. 机器无冲突项进入自动覆盖集合；这只表示机械标准对齐。
3. 只有16个标准—字体冲突和1个缺上下文任务进入复核队列。
4. Onon、蒙科立、参考字体和截图作为冲突证据按需补充，不再要求每条任务机械填写。
5. 对冲突 glyph 标明字形、连接、变体、间距或缺字原因，再形成批准或拒绝记录。

## 尚未完成且不能伪装完成的部分
